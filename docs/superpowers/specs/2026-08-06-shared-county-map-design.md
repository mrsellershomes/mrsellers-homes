# Shared county map: bring the homepage preview card to /towns/

Date: 2026-08-06
Status: approved (Tyler chose full parity + shared module)

## Problem

The Bergen County map appears on two pages with two separate implementations:

- **Homepage** (`index.html`): inline IIFE. Fetches the SVG, injects it, and wires a
  live preview card — hover (mouse) or tap (touch) a town to see its median sale
  price, homes sold, and % of list price, with a per-town CTA.
- **`/towns/`** (generated by `scripts/generate-towns-index.js`): SVG is inlined at
  build time. Clicking a town navigates. No stats, no preview.

Two copies of the same feature already caused one production bug: the homepage sized
the injected SVG `width:auto; height:100%`, which resolves to 0x0 in WebKit, so the
map was invisible on every iPhone. `/towns/` had the correct `width:100%; height:auto`
the whole time. Nothing kept them in sync. Adding the interaction logic as a second
copy would reproduce that failure mode for behavior instead of layout.

## Decision

Extract the map behavior into one shared browser script, `js/county-map.js`, used by
both pages. Tyler chose **full parity**: on touch, the first tap previews and sticks,
and the CTA commits — identical to the homepage — accepting that reaching a town
report from the map on mobile takes two taps.

## Design

### `js/county-map.js`

One IIFE, no build step, no dependencies. Matches the existing plain-ES5-style browser
scripts in `js/`. Activates only if `#countyMap` exists, so it is inert elsewhere.

Configuration via data attributes on `#countyMap`, so the module has no per-page
branching:

| Attribute | Meaning |
| --- | --- |
| `data-map-src` | If present, fetch this SVG and inject it (homepage). If absent, use the SVG already inline (`/towns/`). |
| `data-map-max-height` | Optional inline `max-height` for the injected SVG. |

**Defaults are snapshotted from the DOM at init**, not hardcoded. On load the module
records the initial text of every stat slot plus the CTA's text and href; `reset()`
restores that snapshot. This lets each page declare its own idle state in markup —
the homepage keeps "Browse all 70 towns", `/towns/` points at its own A-Z list — with
zero configuration in JS.

Expected element ids on both pages (all optional; `setText` no-ops when missing):
`mapTownName`, `msMedian`/`msMedianL`, `msSold`/`msSoldL`, `msPct`/`msPctL`,
`mapPeriod`, `mapCta`.

### Behavior (identical on both pages)

- Fetch `/assets/town-stats.json`; on success rewrite `#mapPeriod` to the real period.
- Mouse: `mouseenter` previews a town, `mouseleave` resets unless a town is stuck.
- Touch (`matchMedia('(hover: none)')`): tap calls `preventDefault()`, fills the town
  red, previews it, and points the CTA at that town's report. The CTA navigates.
- Hint text swaps `.hint-hover` -> `.hint-touch` on touch devices.
- `window.__showTownOnMap` stays exported for the homepage search box.
- Fails soft at every step: a failed stats fetch leaves the idle card; a failed SVG
  fetch leaves the homepage's static `<img>`.

### Sizing

The injected SVG is always set to `width:100%; height:auto` (plus optional
`max-height`). The SVG has a `viewBox` but no intrinsic width/height, and `width:auto`
against a flex parent with no definite height collapses to 0x0 in WebKit. This is the
bug fixed in c163e9e and the module is the single place it can regress.

### `/towns/` markup changes

`scripts/generate-towns-index.js` gains the same card structure the homepage uses:
town-name headline above the map, three-stat row below, period caption, CTA. The map
keeps its `<details>` wrapper on mobile; the stats sit inside it so collapsing the map
collapses its readout too. Idle CTA points at the A-Z grid on the same page.

## Out of scope

- The `/towns/` filter box will not drive the map. It filters the A-Z list only.
- The 3 towns with thin data still render an en dash for median. Existing behavior.

## Verification

- `npm test` — extend `towns-index.test.js` to assert the card ids and script tag are
  present in the generated page.
- Both pages measured in real WebKit (Safari) and Chromium at mobile and desktop
  widths. The homepage must still report a non-zero map: this refactor touches the
  code path fixed hours earlier, so re-measuring it is mandatory, not optional.
